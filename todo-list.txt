Paper inconsistencies (latex/main.tex), found 2026-10-22. Most important first.

TEXT DISAGREES WITH THE CODE OR THE FIGURES

DONE 1. Forward-looking sonar doesn't do what the paper says. The paper (Imaging Modalities, FLS appendix) says it applies absorption, no spherical spreading, and an optional time-varying gain. The code always turns spreading on (accumulate_scatters.py and the public package's scatter.py hardcode spherical_spread = True) and has no absorption or gain setting. The FLS parameters table has no kappa or eta rows. Fix the code or the text, then re-render every FLS figure. Worst case is the Sonar Ray Density Across Range figure: the text blames all of the far-range darkening on the rays spreading apart, but about 12 of the 29 dB (range 6 to 12) is the 1/z^2 term.

2. SAR appendix figures are out of date. Rendered 2026-07-16, before the car, pose and linear-trajectory defaults were set, and they show a different car orientation from Fig. 2b, so "the car of Figure 2a ... varied from the defaults of Table A1" is not true for them. The azimuth-spread figure goes to 360 deg, which the default linear trajectory can't fly (generate_trajectory requires < 180 deg), and has raw panel titles like "azimuth_spread0.00e+00". The wavelength figure has 8 values while sar_paper_figures.py now makes 5. Re-render at the current defaults.

DONE 3. calculate_rcs.py is cited in the Reproducibility appendix for the RCS figure (a, b) but is not in the public repo's experiments folder. It only exists in this research repo.

DONE 4. The FLS beam-width sweep breaks the paper's own fan-margin rule. The FLS appendix says the fan must be about 3 beam widths wider than the image span or the edges darken. The Sonar Beam Width appendix sweeps the beam to 10 deg with the fan fixed at 10 deg and the image at 9.15 deg, so the rule fails above 0.28 deg, and the text doesn't mention it.

THE TEXT CONTRADICTS ITSELF

DONE 5. Compute Time: "On the CPU, the time grows faster than the number of rays and the number of triangles" is wrong for triangles. The CPU time grows only 6.6x, 13.8x and 15.3x for 104x more triangles.

DONE 6. Conclusions say the method keeps the signal band-limited "instead of interpolating returns onto the sample grid". The Method says accumulation and interpolation "interpolates each of them onto the sample grid". 

DONE 7. Bandwidth and Ray Density: at B_s = 64 with the default rays the SAR image is said to be clean, then "the SAR image needs about twice the default rays per side" without saying at which B_s. The 2x only applies at B_s = 64. At the default B_s = 30 the default 208 rays are enough (about 176 needed).

DONE 8. SAR wavelength appendix blames the interference on wavelengths "much shorter than the ray grid spacing". The spacing is 1.2/208 ~ 0.006 l, but the panels that show interference are lambda = 0.01-0.02, which are longer than that.

DONE 9. Abstract claims "different noise types", but the body only shows AWGN at a set SNR. Speckle and noise_type are never described, and the SAR parameters table has no noise_type row. Describe them or drop the claim.

PHYSICAL SCALE

DONE 10. The default SAR wavelength (0.5 l, 2.5 m) is comparable to the 0.9 l (4.5 m) car, but Limitations says the model only holds for targets much larger than the wavelength. The car's RCS plot uses this wavelength too.

DONE 11. The units table pairs a 900 MHz bandwidth with a 120 MHz carrier, which no real radar can do.

DONE 12. The units table's sonar column uses B_s = 30 and F_s = 60, but the FLS default is 32 and 64.

MINOR

DONE 13. "l" is both the unit of length and the along-track offset (l_i, S_l, "centered on l = 0") in the side-scan appendix. Rename the offset.

DONE 14. SAR trajectory appendix says the circular path lights the scene more evenly because the range stays nearly constant. SAR uses a planar wavefront with no spreading loss, so range can't change brightness, and the two panels look almost the same.

DONE 16. The intro overview of the signal simulation figure describes a parallel ray grid for every modality, but the sonars cast a point-source fan and FLS traces only once.

DONE 17. Spotlight-Mode SAR appendix: with e^{j2 pi r Z} and Z in cycles, the backprojection should have no 1/(4 pi^2) factor. That factor belongs to the angular-frequency convention.

DONE 18. The materials tables use the column order R, A, S, I, D, while everywhere else the order is (R, A, I, D, S).

DONE 19. Per-Triangle Materials says the constant render gives "every triangle the same material", but the CVDomes materials appendix says its ground is asphalt.

DONE 20. Conclusions say sample rate was varied, but F_s is always 2B_s, and the list of appendix SAR sweeps leaves out noise.
