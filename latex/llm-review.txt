2. NEW SERIOUS PROBLEMS
-----------------------

DONE - Material tables contradict the equations.
DONE     obj_raids = (1.0, 1.0, 100, 0.1, 0.9) breaks both stated constraints: R+S+A = 1 (here 2.9) and
DONE     I+D = 1 (here 100.1). The code (utils.py:30, correct_material_properties) silently normalizes.
DONE     After normalizing, the car has S ~ 0.31 and the ground S ~ 0.05, contradicting main.tex:186-188
DONE     (metal has low scattering, ground clutter high). The exponent alpha is in no table.
DONE     This is exactly R1's reproducibility complaint: show normalized values plus alpha.

- "Stripmap-mode SAR" isn't really stripmap.
    Table 1 and Appendix A.4 describe the same parallel rays aimed at the scene origin over a linear
    path as spotlight mode; only image formation differs. Appendix A.4 even checks it against
    spotlight on "the same signals". Stripmap is defined by acquisition (fixed antenna pointing, a
    footprint that sweeps across the scene), not by backprojection; a SAR reviewer will call it
    mislabeled. Also a mismatch: signals simulated with a far-field planar wavefront but imaged with
    exact near-field range.

- Sonar experiment text doesn't match the default-parameter tables.
    - FLS text: ||v|| = 1.3, 1024x1024 rays, Theta_h = 100 deg, Theta_w = 60 deg,
      rho_near/rho_far = 0.75/3, B_s = 30.
    - SSS text: ||v|| = 10, 700x250 rays, Theta_h = 30 deg, L = 1.1.
    - Appendix tables: 7.5 for both, 350x550 or 550 rays, 23 deg, L = 1.2, B_s = 32, and
      image_range_swath in place of rho_near/rho_far.
    Text describes the configuration from before the Sept 30 - Oct 4 retune. Either re-run and
    re-measure, or state which values override the defaults. Also check whether the sonar figures
    came from the old or the new config.

- SAR bandwidth section blames the wrong cause.
    main.tex:538 and the conclusion (main.tex:771) say artifacts come from "oversampling". Sample
    rate alone can't cause them; the cause is the pulse becoming narrower than the spacing between
    ray returns. The sonar sections (main.tex:647, main.tex:728) explain it correctly, so the paper
    contradicts itself. Conclusion's "without aliasing or distortion" (main.tex:760) overclaims.

- Abstract and intro claim things the body doesn't support.
    - "Supports radar cross section modeling, different noise types": RCS appears nowhere in the
      body; the only noise is an SNR sweep.
    - "Multi-bounce": exactly two bounces.
    - "Lack of open-source ... sonar simulators" is false: HoloOcean, Stonefish, and the DAVE/Gazebo
      sonar plugins are open source, and Related Works cites no sonar work at all.
    - "Validate the stripmap reconstruction against spotlight" only checks the simulator against
      itself; not validation.

DONE - "Energy" is used as a field amplitude.
DONE     The coherent sum sum_k E_k e^{j phi} adds energies as if they were complex fields.
DONE     validation_plate.py treats |sum|^2 as RCS, which only works if E_k is an amplitude. Rename or
DONE     justify.
